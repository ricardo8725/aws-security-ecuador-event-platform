# Design Document — AWS UG Security Ecuador

## Overview

AWS UG Security Ecuador is the community website and event platform for the AWS
Security user group in Ecuador. It is a serverless, static-first architecture
hosted entirely on AWS, managed with Terraform, and deployed via GitHub Actions.

The platform serves a main community site plus three independent sub-sites, and
provides an event registration system with QR-based check-in for in-person
events (notably "AWS GenAI Security Day", 18 July 2026 at Universidad Ecotec,
Guayaquil).

## Goals

- Public, fast, low-cost community presence (static sites on S3 + CloudFront).
- Self-service event registration with email confirmation and a digital QR ticket.
- Staff check-in flow that validates QR codes at the event entrance.
- LOPDP (Ecuador data-protection law) compliance for attendee data.
- Infrastructure as Code, reproducible deploys, and security scanning in CI.

## Non-Goals

- User accounts / authentication for attendees (registration is anonymous-by-email).
- A CMS or dynamic content management — content is hand-authored static HTML.
- Multi-region/HA beyond what CloudFront edge caching provides.

## High-Level Architecture

```
                          ┌─────────────────────────────────────────┐
                          │              Route53 (DNS)               │
                          │   awssecurityecuador.com + subdomains    │
                          └─────────────────────────────────────────┘
                                            │
              ┌─────────────┬───────────────┼───────────────┬──────────────┐
              ▼             ▼               ▼               ▼              ▼
        www (main)    aisecurity        sponsors         register      qr (CDN)
        CloudFront    CloudFront        CloudFront       CloudFront     CloudFront
              │             │               │               │              │
              ▼             ▼               ▼               ▼              ▼
         S3 (site)    S3 (site)         S3 (site)       S3 (site)     S3 (private)
                                            │               │
                                            ▼               ▼
                                      API Gateway      API Gateway
                                      (sponsors)       (register/checkin)
                                            │               │
                                            ▼               ▼
                                   Lambda (sponsors)   Lambda (register)
                                            │           Lambda (checkin)
                                            ▼               │
                                          SES               ▼
                                                    DynamoDB + SES + S3(QR)
```

All static content is served from S3 via CloudFront with Origin Access Control
(OAC); buckets are private and only reachable through CloudFront.

## Components

### Frontend (static sites)

- Plain HTML, Tailwind CSS via CDN, vanilla JS. No build step.
- Dark theme, GitHub-inspired palette; Inter + JetBrains Mono fonts.
- Sites:
  - `index.html` (+ `css/`, `js/`, `assets/`) — main community site
  - `aisecurity/` — AWS GenAI Security Day event microsite
  - `register/` — registration form (`index.html`) + staff check-in (`checkin.html`)
  - `sponsors/` — sponsor inquiry page

### Backend (serverless)

- **register Lambda** (`lambda/register/handler.py`, Python 3.12)
  - Validates payload, verifies Cloudflare Turnstile, enforces capacity,
    prevents duplicates, writes to DynamoDB, generates QR, uploads to S3,
    sends confirmation email via SES.
- **checkin Lambda** (`lambda/checkin/handler.py`)
  - Staff-secret authenticated; validates QR/code, marks attendee checked-in,
    lists attendees (filtering out internal lock items).
- **sponsors Lambda** (`lambda/sponsors/handler.py`)
  - Validates inquiry, sends notification email to `sponsors@awssecurityecuador.com`.

### Data store

- Single DynamoDB table `awssecurity-ecuador-registrations` (PAY_PER_REQUEST).
- Global Secondary Indexes: `email-index` (hash: email), `event-index` (hash: event).
- Point-in-time recovery and SSE enabled.

### Email

- Amazon SES (production access; 50k/day, 14/sec) sends from
  `noreply@awssecurityecuador.com`.
- Inbound handled by iCloud Custom Domain catch-all (single mailbox receives
  `*@awssecurityecuador.com`).
- DNS auth: SPF (`amazonses.com` + `icloud.com`), DKIM (SES x3 + iCloud), DMARC
  (`p=quarantine`).

### QR code delivery

- Generated by the register Lambda, uploaded to a private S3 bucket
  (`...-qrcodes-...`) under `qr/<registration_id>.png`.
- Served via a dedicated CloudFront distribution (OAC, bucket private).
- Email embeds the CloudFront URL (not base64) so Gmail/Outlook/Yahoo image
  proxies can render it. Lifecycle rule expires objects after 90 days.

## Data Model

DynamoDB items share one table, keyed by `registration_id` (String):

**Registration item**
```
registration_id   : <uuid>
registration_code : <8-char code>      # printed on the digital ticket
event             : aws-gen-ai-security-day-2026
email, first_name, last_name, phone, company, role
experience, ai_experience, city
expectations
consent_data, consent_communications, consent_image (bool)
registered_at     : ISO8601
checked_in        : bool
checked_in_at     : ISO8601 | null
```

**Email-lock item (duplicate prevention)**
```
registration_id : EMAIL_LOCK#<email>#<event>
email, event, lock_type=email_uniqueness, created_at
```

The lock item and registration item are written together with
`TransactWriteItems` (both `attribute_not_exists` conditions) to atomically
prevent TOCTOU duplicate registrations under concurrency.

> Note: lock items carry an `event` attribute and therefore appear in
> `event-index`. Capacity counting and attendee listing must exclude items where
> `lock_type` exists / `registration_id` starts with `EMAIL_LOCK#`.

## Key Flows

### Registration

1. Browser POSTs form data + Turnstile token to `POST /api/register` (CloudFront → API GW → Lambda).
2. Lambda validates input (types, email/phone regex, allowed enums, consent).
3. Verifies Turnstile with Cloudflare.
4. Counts current registrations via `event-index` (excluding lock items);
   rejects with 409 if `>= MAX_REGISTRATIONS` (400).
5. Rejects duplicates (generic 409 to avoid email enumeration).
6. `TransactWriteItems`: registration item + email-lock item.
7. Generates QR, uploads to S3, builds CloudFront URL.
8. Sends confirmation email (HTML + text) via SES with code + QR.
9. Returns `registration_code` and `spots_remaining`.

### Check-in (staff)

1. Staff opens `checkin.html`, provides the staff secret (sent as `X-Checkin-Secret`).
2. Scans QR (or enters 8-char code).
3. `POST /api/checkin` looks up by id or code, validates, sets `checked_in=true`.
4. `GET /api/attendees` lists attendees with status (lock items filtered out).

### Deploy

1. Push to `main` (or manual dispatch) triggers GitHub Actions.
2. OIDC role assumption (no static AWS keys).
3. Snyk IaC scan (blocks on HIGH/CRITICAL) + Snyk Code SAST (non-blocking).
4. `terraform init/plan/apply`.
5. `aws s3 sync` per site (dotfiles excluded), then CloudFront invalidations.

## Security Design

- **Buckets private**: all S3 buckets block public access; access only via
  CloudFront OAC with `AWS:SourceArn` condition.
- **Dotfile protection**: S3 sync excludes dotfiles; a CloudFront Function
  (`block-dotfiles`) returns 403 for any path segment starting with `.` on all
  distributions (defense in depth against exposing `.gitignore`, `.env`, etc.).
- **Security headers**: custom CloudFront response-headers policy (HSTS, CSP,
  X-Content-Type-Options, frame options, referrer policy).
- **Geo restriction**: distributions whitelist `["EC", "US"]`. The QR CDN uses a
  broader whitelist so global email image proxies can fetch QR images.
  - Gotcha: a `custom_error_response` mapping 403→200/index.html will mask geo
    blocks, so the 403 fallback was removed (404 fallback kept).
  - Gotcha: switching geo `whitelist`→`none` in-place fails with
    `InvalidGeoRestrictionParameter`; use a broad whitelist instead.
- **Secrets**: check-in staff secret stored in SSM Parameter Store (SecureString),
  read at runtime; Turnstile secret injected as Lambda env var. No secrets in code.
- **Input handling**: fail-closed validation, URL stripping in free-text (SSRF
  prevention via email), HTML-escaping of user content in emails, email masking
  in logs.
- **Bot protection**: Cloudflare Turnstile on registration.
- **CI scanning**: Snyk IaC (blocking) + Snyk Code SAST; local pre-push hooks for
  Checkov and Snyk.

## Infrastructure (Terraform)

- Backend: S3 with DynamoDB state locking, region `us-east-1`.
- Provider: AWS `~> 5.0`, Terraform `>= 1.5.0`.
- Files split by concern: `s3`, `cloudfront`, `route53`, `acm`, `iam`, `ses`,
  plus per-sub-site files (`aisecurity`, `register`, `sponsors`).
- ACM certificates in `us-east-1` (required for CloudFront).

## Capacity & Limits

- Registration cap: `MAX_REGISTRATIONS = 400` (real registrants; lock items excluded).
- API Gateway throttling: 20 req/sec sustained, 50 burst (shared across routes).
- Check-in: no per-device limit; staff share one secret. Practical ceiling is the
  API throttle (~20 check-ins/sec), far above any realistic staff scanning rate.
- DynamoDB on-demand and Lambda default concurrency are not the bottleneck.

## Known Trade-offs / Future Work

- Tailwind via CDN requires `unsafe-inline`/`unsafe-eval` in CSP; a build step
  would allow a stricter CSP.
- Lambda dependencies are vendored (no `requirements.txt`), so Snyk SCA cannot
  scan them; adding a manifest would enable dependency scanning.
- Snyk Code SAST step is non-blocking; can be made blocking now that Snyk Code
  is enabled on the org.
- Static asset and content management is manual.
